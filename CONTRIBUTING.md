# Contributing to OpenPulse

Thank you for considering a contribution.

## Ways to contribute

- Report reproducible bugs.
- Improve accessibility, browser compatibility, or documentation.
- Suggest a focused utility that fits the project's goals.
- Submit a small, clearly explained pull request.

## Before opening an issue

1. Search existing issues to avoid duplicates.
2. Describe the expected behavior and what happened instead.
3. Include browser and operating-system details when relevant.
4. Never include passwords, API keys, personal data, or other secrets.

## Pull request guidelines

1. Fork the repository and create a branch for your change.
2. Keep changes focused and explain the reason for them.
3. Test the affected tool manually in a modern browser.
4. Check that user input remains in the browser and is not sent to an external service.
5. Update the README if behavior or project structure changes.
6. Open a pull request with a concise summary and testing notes.

## Code guidelines

- Prefer plain, readable JavaScript, HTML, and CSS.
- Avoid adding dependencies unless they provide clear value.
- Handle invalid input with understandable messages.
- Preserve keyboard accessibility and responsive layouts.
- Do not add analytics, tracking, remote input processing, or hidden network requests.

## Community standards

Be respectful, constructive, and welcoming. Explain disagreements with evidence and focus feedback on the work, not the person.

By contributing, you agree that your contributions are provided under the repository's MIT License.
